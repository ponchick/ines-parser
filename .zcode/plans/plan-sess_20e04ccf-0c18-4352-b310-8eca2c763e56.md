# Архитектура записи iNES: новый проект ines-file + релиз ines-parser 2.0

## Контекст

`ines-parser` (MIT, v1.5.1) умеет только читать. Появилась задача записи: сериализация заголовков, сборка ROM из PRG/CHR-частей, правка существующих ROM. Решение (согласовано): ines-parser остаётся парсером в своём репозитории и получает релиз 2.0; запись реализуется в **новом самостоятельном проекте `ines-file`** (репо уже создан: `~/work/ines-file`, внутри только README.md и .git).

**Источники кода:**
- `famicom-dumper-client-py` (GPL-3.0) — **код не переносится вообще**. Проект используется только как перечень функционала записи, который точно нужен. Ваш будущий MIT-«lite» дампер будет потреблять ines-file вместо этого модуля.
- `ines-parser` (MIT, ваш проект) — можно брать практически всё как есть: енумы, константы, конвенции CLI, конфигурацию инструментов, docstring-стиль.

Writer реализуется по публичной спецификации из `ines-parser/docs/iNES.md` и `docs/NES2.0.md`. Работаю с обеими папками по абсолютным путям, новый zcode-проект не нужен.

## Часть 1 — новый проект `ines-file` (~/work/ines-file)

Самостоятельный пакет (без зависимости от ines-parser в рантайме), MIT, Python ≥3.10, deps=[] (stdlib only), py.typed. В скоупе — только контейнер iNES/NES 2.0: filename-теги GoodTools и база мапперов остаются в ines-parser (при желании tables.py можно перенести позже — он MIT).

**1. Каркас** (по конвенциям ines-parser): `pyproject.toml` (dist name `ines-file`, import `ines_file`, v1.0.0, setuptools, tool-секции black/mypy/pylint как в ines-parser), `LICENSE` (MIT), `README.md` (EN), `CHANGELOG.md`, `.gitignore`, `ines_file/py.typed`.

**2. `ines_file/enums.py`** — `Mirroring` (H/V/F), `ConsoleType`, `CPUTiming`, `TVSystem` — переносим из `ines_parser/parser.py` как есть (MIT), что даёт единый словарь для всей экосистемы.

**3. `ines_file/header.py`** — `@dataclass class INESHeader` (мутабельный — удобен для правки):
```python
mapper: int = 0; submapper: int = 0
prg_rom_size: int = 0; chr_rom_size: int = 0        # байты
mirroring: Mirroring = HORIZONTAL
has_battery/has_trainer/four_screen: bool = False
console_type: ConsoleType = NES_FAMICOM
nes2_0: bool = False                                 # явный выбор формата при записи
# NES 2.0 (None = не задано):
prg_ram_size / prg_nvram_size / chr_ram_size / chr_nvram_size: int | None  # байты, степени двойки
cpu_timing: CPUTiming | None; vs_ppu_type / vs_hw_type / expansion_device / misc_rom_count: int | None
```
Методы: `from_bytes(b: bytes)` — строгий парсинг iNES 1.0 + NES 2.0 (ValueError на мусор; archaic/iNES 0.7/UNIF отклоняются с внятной ошибкой), `to_bytes()` — каноническая упаковка по спецификации: флаги 6–15, биты NES 2.0 в byte 7, byte 8 (mapper MSB + submapper), byte 9 (MSB размеров или экспоненциальная нотация для >255 юнитов), bytes 10–11 (shift-кодирование RAM), byte 12 (timing + VS/expansion), byte 13, byte 14 (misc), byte 15 (expansion). Валидации при записи: mapper>255 / submapper≠0 / RAM задан ⇒ требуется NES 2.0; NVRAM ⇒ battery; RAM — степени двойки; trainer — ровно 512.

**4. `ines_file/file.py`** — `@dataclass class INESFile`: `header`, `trainer`, `prg`, `chr`. Методы: `from_file(path)` / `from_bytes(data)` (строгие, нарезка по заголовку, флаг усечённого файла), `to_bytes()` (юниты считаются из длины данных; короче объявленного — добивка 0xFF; длиннее — ValueError; trainer-бит по факту наличия данных, несовместимость — ошибка), `save(path)`. Round-trip: `from_bytes(x).to_bytes() == x` для корректных файлов.

**5. `ines_file/cli/ines_build_rom.py`** — CLI по конвенции проекта (main() -> int, `build_argument_parser()`, диагностика в stderr, отказ перезаписывать без `--force`, executable, entry point в console_scripts). Два режима:
- сборка: `--prg F --chr F [--trainer F] --mapper N [--submapper] [--mirroring V|H|F] [--battery] [--nes20] [--timing ...] [--prg-ram/--prg-nvram/--chr-ram/--chr-nvram BYTES] -o out.nes`
- клон/правка: `--clone src.nes [--set-mapper] [--set-submapper] [--set-mirroring] [--set-timing] [--set-ram ...] [--upgrade-nes20] [--strip-trainer] -o out.nes`

**6. Тесты** (`tests/`, pytest, заголовки синтезируются в тестах — реальных .nes в репо нет): `test_header.py` — побайтовые ожидания (MMC3-классика, mapper 34 high nibble, battery, NES 2.0 с submapper, RAM-shift 8192→shift 7, экспонента для >4095 KiB), все гарды; `test_file.py` — round-trip байт-в-байт, trainer, усечение/добивка, ошибки; `test_cli.py` — оба режима, коды возврата; кросс-валидация с ines-parser (`pytest.importorskip("ines_parser")`): собираем ines_file → парсим ines_parser → поля совпадают.
